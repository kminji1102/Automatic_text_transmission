# 인터뷰 SMS 자동 발송 서비스 정의서 (v4.0)

> 작성일: 2026-05-22
> 버전: v4.0
> 변경 이유:
> - 기수 필드 부분 일치(contains) 매핑 추가 — 노션 기수 필드값이 "33기"가 아닌 "SFAC 33기" 등 다양할 수 있음
> - 노션 자동 조회 ≠ 자동 발송 구분 명시 — 조회는 자동, 발송은 담당자 확인 후 수동

---

## 0. Executive Summary

**한 줄 정의**: 노션 인터뷰 DB에서 당일 예정자를 자동으로 읽어오고, 담당자가 목록을 확인한 뒤 버튼을 눌러야 뿌리오로 발송되는 사내 발송 보조 도구

**핵심 문제**: 뿌리오에서 수신자를 한 명씩 입력하고, 기수별 발신번호를 직접 바꿔가며 반복 발송하는 작업이 오래 걸리고 실수가 생긴다.

**우리 해결책**: 노션 DB에서 오늘 예정자를 자동으로 가져오고, 기수 필드값에 "33기" 또는 "34기"가 포함되어 있으면 해당 발신번호를 자동으로 매핑한다. 담당자는 목록을 확인하고 Y를 누르면 된다.

**1단계 MVP 범위**: 노션 자동 조회 → 기수 포함 여부로 발신번호 자동 매핑 → 목록 미리보기 → **담당자 확인 후** 발송 → CSV 결과 기록

**기대 효과**: 발송 준비 시간 대폭 단축 / 기수 혼동 발송 실수 0건 / 담당자 1인이 4주 내 직접 배포 가능

---

## 1. 한 문장 서비스 정의

채용 운영 담당자가 프로그램을 실행하면 노션 DB에서 당일 인터뷰 예정자를 자동 조회하고, 기수 필드에 "33기"·"34기" 등이 포함되어 있으면 해당 발신번호를 자동으로 매핑해 목록을 보여준 뒤, **담당자가 확인 후 Y를 입력해야** 뿌리오 API로 고정 문구를 일괄 발송하고 결과를 CSV에 저장하는 사내 운영 Python 스크립트

---

## 2. 타깃 사용자

- **누구**: 채용 운영 담당자 1명 (사내 HR팀)
- **현재 행동**: 노션을 열어 당일 인터뷰 행 확인 → 기수별로 뿌리오 발신번호를 바꿔가며 수신자를 한 명씩 입력 → 문구 복붙 후 발송

---

## 3. 핵심 가치 제안

**Before**: 노션 확인 → 기수 구분 → 번호 선택 → 뿌리오 수동 입력의 4단계가 매일 반복된다.

**After**: 프로그램을 실행하면 노션 조회와 기수 매핑이 자동으로 된다. 담당자는 **목록만 눈으로 확인하고 Y를 누르면** 끝난다.

> ⚠️ 중요: 노션 조회는 자동이지만 **발송은 자동이 아닙니다**. 담당자가 목록을 확인하고 Y를 입력해야만 발송됩니다.

---

## 4. 대표 사용 시나리오

### 시나리오 1: 정상 발송
- **상황**: 노션에 오늘 예정자 5명. 기수 필드값이 "SFAC 33기 수강생", "플레이데이터 34기" 등 다양한 형태로 입력되어 있음
- **행동**: 프로그램 실행 → 기수 필드에 "33기" 포함 여부 자동 확인 → 발신번호 자동 매핑 → 목록 표시 → Y 입력
- **결과**: 33기 포함 3명은 서초캠퍼스 번호로, 34기 포함 2명은 G밸리 번호로 발송 완료

### 시나리오 2: 기수 매핑 불가
- **상황**: 기수 필드값이 "35기 수강생"인데 config.py에 35기 등록 안 됨
- **결과**: 해당 건 `매핑없음`으로 처리, 나머지는 정상 발송. logs/ CSV 상단에 경고 표시

### 시나리오 3: 중복 발송 방지
- **상황**: 실수로 같은 날 두 번 실행 후 Y 입력
- **결과**: 오늘 이미 성공 발송된 번호는 자동 제외, CSV에 `중복건너뜀` 기록

### 시나리오 4: 담당자가 목록 확인 후 취소
- **상황**: 미리보기를 보니 발송 목록이 이상함
- **결과**: N 입력 → 발송 없이 종료. 노션에서 내용 수정 후 재실행 가능

## 5. MVP 단계별 범위

### 1단계 (4주, 현재 목표) — 핵심 기능 2개

| # | 기능 | 포함 이유 |
|---|---|---|
| **핵심 1** | 노션 자동 조회 + 기수 **포함 여부**로 발신번호 자동 매핑 + 목록 미리보기 + **담당자 Y/N 확인 후** 발송 | 핵심 자동화 — 없으면 현재 수동 방식과 차이 없음 |

## 6. 기술 구조 요약 (1단계)

```
[담당자가 python main.py 실행 또는 run.bat 더블클릭]
                    ↓
        ── 자동 처리 구간 ──────────────────
        [노션 API] → 오늘 예정자 자동 조회
                    ↓
        [기수 필드에 "33기" 포함? → 서초번호]
        [기수 필드에 "34기" 포함? → G밸리번호]
                    ↓
        [오늘 이미 성공 발송된 번호 자동 제외]
        ── 자동 처리 구간 끝 ────────────────
                    ↓
        [발송 목록 터미널 미리보기 표시]
                    ↓
        ★ 담당자가 목록 확인 후 Y 입력 (수동)
                    ↓
        [뿌리오 API] → 고정 문구 일괄 발송
                    ↓
        [logs/YYYY-MM-DD.csv] → 결과 저장
```

## 7. 다음 단계 입력 요약본

### 잠긴 결정 (Locked)
- 노션 조회: 자동 (`인터뷰일시` = 오늘 KST)
- 발송: 수동 (담당자 Y 입력 필수)
- 기수 매핑: `config.py` `COHORT_SENDER_MAP` 하드코딩, **포함(contains) 방식**으로 매핑
- 문자 내용: 고정 문구 (동적 변수 없음)
- 중복 방지: 같은 날짜 + 같은 연락처 성공 발송 기록 → 건너뜀
- 결과 기록: `logs/YYYY-MM-DD.csv` (UTF-8-BOM)
- 환경 변수: `NOTION_TOKEN`, `PPURIO_ID`, `PPURIO_KEY`
